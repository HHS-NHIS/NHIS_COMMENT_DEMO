# NHIS 2028 Redesign — Public Comment Intelligence Dashboard

**Current release: V10.10.1 (October 24, 2026).** Docket CDC-2026-1387 contains **3,748 publicly posted/indexed comment records** in the October 21, 2026 public API inventory used for this frozen analytical release. This is not a count of all submissions received or unique respondents.

**Live dashboard:** https://nhis-v108-full-dashboard-production.up.railway.app/

The dashboard is a public, read-only, unofficial research prototype, not a certified CDC analysis. Model-assisted classification, clustering, prioritization scores and narratives are provisional; independent substantive/agency review is still needed. The public service does not make paid model calls or permit updates to the source database.

## What is included

- Core overview, evidence search, AI classifications, theme analysis, comment explorer, response review (where allowed), Corpus QC and downloads.
- **Management Analysis** with eight nonexclusive reporting sections, 30 original AI themes, 15 additional topics, optional second added-topic overlap, Primary/Secondary topic roles, conditional Content request types, evidence links, and an identified/not-identified form-letter flag. Saved full-corpus Word reports reflect the original precompiled management methodology and are not regenerated by these filters.
- **Issue Prioritization & Impact Analysis**: a separate source-linked, AI-assisted screening ledger containing 201 issues and 1,464 extracted recommendations. Five-part scoring is interpretive and **not validated policy impact**. The source quotations, references and scoring arithmetic are checked; interpretations still need review.

The older 48-group / 2,908-submission figures remain visible in the unchanged Corpus QC tab because they use the earlier frozen grouping. The issue-prioritization ledger may use another volume definition; do not silently equate it with either grouping. Repetition does not imply identical people, coordinated campaigns or identical substantive arguments.

## Fresh-checkout release verification

Git stores the frozen public database in compressed pieces under **payload_parts/**, not as an immediately openable database. From the repository root, with Python 3.12+:

~~~sh
python scripts/run_release_qc.py
~~~

This reconstructs the 3,748-record public database with `scripts/unpack_payload.py`, runs `scripts/verify_public_release.py`, then executes the **current release's** versioned suites: `test_v107_*`, `test_v108_*`, `test_v1082.py`, `test_v109_*`, `test_v110_*`, and `test_v111_*`. It uses the same hosted/read-only settings as the Docker build. It stops on error and requires no paid API key. The general command `python -m unittest discover -s tests` includes unrelated legacy pilot-era tests and **is not** this version's release gate.

Alternatively, from the repository root:

~~~sh
docker build -t nhis-comment-intelligence:qc .
~~~

Railway builds the Dockerfile, verifies all public records and management report hashes, runs the versioned tests, and serves the public database in immutable read-only mode. The live service is in Railway project `60545997-0ff2-4a17-b417-b4c562b6cc9b`.

## Methodology and limits

- Each count is a comment record, not a unique person or independently adjudicated request; categories and topics are multi-label.
- Topic pairs, including Primary/Secondary, are provisional screening outputs. The current release does not rewrite old full-corpus Word syntheses as users filter.
- Source-linked quotations from issue recommendations were matched against archived public comment and attachment text. Human review of the original documents remains important, especially for OCR or image-only attachments.
- The comment-posting snapshot is dated **October 21, 2026**, not October 20; that does not certify every received comment was indexed.
- Agency cloud/publication approval and independent human adjudication are separate from software QC.
