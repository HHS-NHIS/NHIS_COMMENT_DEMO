# Updating NHIS public comments — controlled local workflow

**Do not update Railway directly.** These steps run on a working copy of the full local analysis project. The public GitHub checkout intentionally has no private review cache or import history. **Confirm agency authorization before publishing data externally.**

1. **Back up** the full local master database and exporter folder. Verify the docket, the export's run timestamp, the last posted ID, and the list of newly available public comments. The number of *submissions received* on the docket is not necessarily the count of publicly posted comments.
2. **Fetch the incremental/new public comments** from Regulations.gov using the existing exporter, saving source CSVs and any attachment files. Preserve original IDs, public posting dates and URLs. Do not overwrite the master with an unverified smaller extract.
3. **Import/sync locally** with the complete cumulative exporter snapshot. Check that IDs are unique, previous records are retained, attachments are linked to the correct IDs, and no substantive text was inadvertently truncated.
4. **Extract newly posted attachments**, and review low-confidence OCR or AI image transcription/description against the originals. Flag documents whose source text cannot be confirmed.
5. **Run the AI classifier locally**: first `python scripts/semantic_classify.py --dry-run` and review its proposed jobs/cost; then, only after authorization, `python scripts/semantic_classify.py --approve-paid-api`. Changed clusters automatically bring their existing copies into reassembly. Existing *identical* cached units are reused. If the shared text really changed, a new template unit **may require a paid model call**; no fixed price or duration is promised. Template-review carry-forward is conservative and logged; verify migrated decisions before relying on them.
6. **QC before publication:** `python scripts/semantic_classify.py --consistency-report`; run `python -m unittest discover -s tests`; audit the counts and newly added/changed records, model evidence quotes, form-letter groups and attachment status. Complete or update independent human-coded validation when feasible.
7. **Build a clean public snapshot** from the *master*, without modifying it: `python scripts/build_public_snapshot.py --source path/to/master.sqlite3 --output-dir path/to/public_export`. Inspect `PUBLIC_SNAPSHOT_MANIFEST.json`, confirm excluded working tables, and publish the public-export parts plus reviewed code to the existing GitHub/Railway project using a controlled commit. Inspect the live `/healthz`, `/api/meta`, search/export routes, and public disclaimer. Do not commit private validation keys, local master databases, API tokens, or internal review records.

**Public snapshot scope:** 1,693 comments are currently in the October 19 export. Received submissions can exceed publicly posted/indexed comments; this gap is not automatically evidence that comments were deleted or withheld.
